# RestEye（眸息）产品需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | RestEye · 眸息 |
| 产品类型 | 跨平台护眼提醒工具 |
| 目标平台 | Android、Windows、macOS |
| 当前阶段 | 需求基线 / MVP 规划 |

本文档记录 RestEye 的功能边界、交互规则、平台约束和后续实现预留。README 只保留项目简介，具体需求以本文档为准。

## 2. 产品目标

帮助用户形成规律的“工作—休息”节奏，降低长时间盯屏带来的眼睛疲劳。产品应做到提醒及时、操作简单、打扰可控，并尽量符合用户所在平台的原生体验。

## 3. 核心概念

- **工作时段**：用户进行屏幕工作的计时阶段。
- **工作提醒**：计划休息时间用完时发出的提醒，提示用户开始下一轮工作。
- **休息提醒**：工作时段结束后发出的提醒，提示用户开始休息。
- **休息时段**：用户确认开始休息后运行的倒计时阶段。
- **未休息提醒**：用户收到休息提醒后仍未开始休息时，按配置重复发送的提醒。
- **未工作提醒**：计划休息时间用完后用户仍继续休息时，按配置重复发送的提醒。

## 4. 功能需求

### 4.1 工作与休息计时

1. 用户可以启动一轮工作计时。
2. 工作计时达到配置的工作时长后，应用发出休息提醒。
3. 默认工作时长为 20 分钟，默认休息时长为 20 秒，体现 20-20-20 护眼规则。
4. 用户可以在应用内直接开始休息。
5. 用户点击“开始休息”后，开始休息倒计时。
6. 休息倒计时结束后，应用提醒用户本次休息完成，并进入下一轮工作准备状态。
7. 用户在等待休息期间不能跳过休息；可以开始休息，或结束当前计时回到待启动状态。
8. 同一时刻只能存在一个活动中的工作计时或休息计时，避免重复计时。
9. 首页活动计时使用正计时：工作阶段显示“已工作”，休息阶段显示“已休息”；工作、提醒和休息状态使用不同颜色区分。

### 4.2 自定义设置

用户可以自定义以下参数：

| 设置项 | 默认值 | 说明 |
| --- | ---: | --- |
| 工作时长 | 20 分钟 | 工作计时达到后触发休息提醒 |
| 休息时长 | 20 秒 | 点击开始休息后运行的倒计时 |
| 工作提醒 | 开启 | 计划休息时间用完时提示开始下一轮工作；三端均可用 |
| 休息提醒 | 开启 | 工作结束后提示开始休息；三端均可用 |
| 未休息重复提醒 | 开启 | 等待休息时按“未休息提醒间隔”重复提醒；三端均可用 |
| 未休息提醒间隔 | 3 分钟 | 收到休息提醒后仍未休息时的重复提醒间隔 |
| 未休息超时时间 | 10 分钟 | 超过该时间仍未休息，则按“超时后处理”结束当前休息等待 |
| 超时后处理 | 进入下一轮 | 选择进入下一轮工作，或直接结束计时 |
| 未工作重复提醒 | 开启 | 继续休息时按“未工作提醒间隔”重复提醒；三端均可用 |
| 未工作提醒间隔 | 3 分钟 | 计划休息时间用完后仍未工作时的重复提醒间隔 |
| 休息超时时间 | 10 分钟 | 继续休息达到该时间后按“休息超时后处理”执行 |
| 休息超时后处理 | 进入下一轮 | 选择进入下一轮工作，或直接结束计时 |
| Android 震动 | 开关 | 控制 Android 通知是否触发震动 |
| 主题模式 | 跟随系统 | 可选择跟随系统、浅色或深色 |
| 显示语言 | 跟随系统 | 可选择跟随系统、中文或英文 |
| 桌面关闭行为 | 保留到托盘/菜单栏 | Windows 关闭窗口后保留到系统托盘，macOS 保留到菜单栏；用户可关闭该行为 |

设置修改后应自动持久化，应用重启后继续使用，不提供需要用户额外点击的全局“保存设置”按钮。连续拖动的数值控件可以短暂防抖后保存；开关和选项修改后应尽快生效。时长设置需要限制在合理范围内，具体范围由实现阶段根据平台交互与系统限制确定；设置组合非法时应提示用户、暂停自动保存并保留最近一次有效设置。保存新时长会停止正在进行的计时（保存时经确认弹框提示，未在计时时直接保存），新时长从下一轮开始使用；这样避免活动计时显示的时长与新设置不一致或看似未生效。

### 4.3 原生通知

提醒必须使用系统原生通知通道，而不是仅依赖应用内弹窗。

通知至少覆盖以下场景：

- 工作时段结束，提示开始休息；
- 用户未开始休息时的重复提醒；
- 休息倒计时完成，提示休息完成；
- 需要时提示计时状态或权限问题。

工作提醒、休息提醒、未休息重复提醒和未工作重复提醒可以分别关闭；两类重复提醒分别使用各自的提醒间隔。

所有计时通知都需要提供“结束计时”操作；休息提醒另外提供操作入口：

- **开始休息**：直接开始休息倒计时；

平台要求：

- Android 使用通知渠道，并正确处理通知权限、后台限制和前台服务/后台计时能力；震动由独立开关控制。
- Windows 使用系统通知能力，并遵循 Windows 通知的交互和权限机制；通知明确请求系统默认提示音，最终是否播放仍遵循 Windows 的应用通知声音、系统音量和专注助手设置。
- Windows 提供“关闭时最小化到托盘”设置，默认开启；macOS 提供等价的“关闭时保留在菜单栏”设置，默认开启。开启后关闭窗口只隐藏应用，原生菜单提供打开和退出；关闭设置后关闭窗口退出应用。
- Windows 和 macOS 真正退出时保存最后一次普通窗口的位置与大小，下次启动在首次显示前恢复；隐藏到系统托盘或菜单栏不覆盖已保存的窗口几何，也不恢复最大化或最小化状态。
- Windows 系统托盘、macOS 菜单栏均根据当前计时状态提供动态菜单：开始工作、继续工作、开始休息、结束休息和结束计时，仅显示当前状态允许的动作；打开和退出不附带应用名称。
- macOS 使用系统通知能力，并遵循 macOS 通知授权与用户操作习惯。
- 通知操作需要具备幂等性：重复点击或通知过期时，不得创建重复计时；应根据当前状态安全忽略或更新操作。
- 通知按钮回调处理期间，同一逻辑提醒不得被截止点对账或恢复补发再次弹出；只有计时状态提交成功后，才把对应操作通知视为过期并取消。
- 系统已经接受排程的通知到达截止点后，不得仅因它已离开待发列表而立即重放；平台无法可靠查询已显示通知时，应优先避免重复弹出和瞬间替换。
- 通知动作应携带所属等待窗口的截止时间；后台恢复处理动作时不得把未知离线时间追赶到点击时刻之外。工作/休息阶段可以提前排程当前有限等待窗口内的重复提醒，状态转换仍由统一领域对账提交。

### 4.4 直接开始与结束

应用主界面应提供清晰可见的操作：

- 工作计时运行时，可以直接开始休息；
- 等待休息或休息提醒状态时，可以开始休息；
- 所有活动计时阶段都可以直接结束计时；
- 休息计时运行时，可以开始下一轮工作。

任何操作都应立即反馈当前状态和剩余时间。

### 4.5 锁屏暂停

1. 开启“锁屏暂停计时”后，处于工作阶段时 Android、Windows、macOS 进入锁屏会暂停工作计时并保留剩余时间；解锁后恢复同一轮工作计时，不重新开始整轮。该开关默认关闭。
2. Windows 使用会话锁定事件，macOS 使用系统锁屏事件，Android 使用系统 Keyguard 状态；显示器单独熄灭但未锁屏时不暂停。
3. 等待休息和休息阶段不因锁屏暂停，避免影响休息提醒和已开始的休息时长统计。
4. 工作被暂停时，首页需要明确显示暂停状态；用户也可以从首页手动继续工作。

### 4.6 未休息提醒与超时处理

1. 工作时长结束后，进入“等待休息”状态并发送首次休息提醒。
2. 如果用户未开始休息，则每隔配置的提醒间隔重复提醒一次；默认间隔为 3 分钟。
3. 从首次休息提醒开始计算未休息等待时间。此时工作进度保持 100%，界面展示的“已工作”时长继续累加，不重新开始进度或显示超时倒计时。
4. 等待休息期间的超时工作须计入工作时长；用户开始休息、停止计时或等待超时后，已累计的超时工作均应写入统计。
5. 当等待时间超过配置的超时时间时，按“超时后处理”执行：默认结束本次休息等待并进入下一轮工作，也可以直接结束计时回到待启动；两种情况都不计为完整休息。默认超时时间为 10 分钟。
6. 用户可以自定义提醒间隔、超时时间和超时后的处理方式。
7. 超时时间应大于提醒间隔；若用户设置不满足约束，应阻止保存并给出明确提示。
8. 超时后已过期的通知操作不得再次启动上一轮休息计时。
9. 应避免重复提醒任务叠加；暂停、开始休息或超时后，需要取消当前等待状态下的后续提醒。

### 4.7 休息完成处理

1. 休息倒计时自然结束时先触发工作提醒，再按“休息结束后”设置执行：自动开始工作、结束计时或继续休息。
2. 选择继续休息时进入休息超时阶段，进度保持 100%，超出计划休息时长的部分继续计入休息时长。
3. 休息超时阶段按“未工作提醒间隔”重复发送工作提醒，达到“休息超时时间”后按设置进入下一轮工作或结束计时。
4. 休息中的主操作显示为“开始工作”；点击后结束当前休息并开启下一轮工作。
5. 休息超时时间必须大于未工作提醒间隔；非法组合不得保存。

## 5. 计时状态与流程

建议以显式状态机实现，核心状态如下：

```text
待启动
  └─开始工作→ 工作中
                └─工作时长结束→ 等待休息
                                      ├─开始休息→ 休息中
                                      │             └─倒计时结束→ 工作提醒→ 待启动/下一轮/继续休息
                                      │                                      └─休息超时→ 下一轮/待启动
                                      └─超时→ 按设置进入下一轮/待启动
```

状态规则：

- 工作中：显示已工作时间，可触发直接开始休息。
- 等待休息：已发出休息提醒，工作进度保持完成，已工作时长继续累加；按配置重复提醒。
- 休息中：显示已休息时间，完成后记录一次休息。
- 休息完成：展示完成反馈，并为下一轮工作做好准备。
- 待启动：没有活动计时，可开始新的工作计时。

所有状态切换都应由统一的计时领域逻辑驱动，通知点击、主界面按钮和锁屏暂停控制都通过同一套状态转换入口执行。

应用启动完成恢复流程后，应自动结束上次进程遗留的活动计时；应用真正退出时，也应通过可等待的退出清理流程，先结束当前活动计时并持久化停止事件，再允许原生宿主结束进程。Windows 窗口退出和托盘退出、macOS 窗口退出和菜单栏退出、Android 根路由返回退出都应进入同一清理语义。最小化到托盘、保留到菜单栏、进入后台、窗口暂时隐藏或锁屏不属于真正退出，不应因此结束计时。任务管理器强杀、系统回收、崩溃和断电不保证提供退出回调；下次启动处理遗留快照时不得把未知的离线时间计入工作或休息。
若应用由通知动作冷启动，应先尝试提交仍在有效窗口内的动作；动作无效后才执行遗留活动清理，并取消该旧轮次的通知。

## 6. 统计需求

应用需要支持统计以下数据：

- 工作时长；
- 休息时长；
- 休息次数。

统计口径：

- 一次休息倒计时正常完成，计为 1 次休息，并累计实际休息时长；
- 等待超时和未完成的休息不计为完整休息；
- 工作计时和休息计时的开始、结束、取消、中途结束应留下可用于统计的事件记录；
- 锁屏状态事件用于锁屏暂停设置下的暂停/恢复；不作为和工作时长并列的用户可见统计指标；
- 统计页面默认查看今天，并支持使用 Material 单日期选择器查看任意已记录日期。
- 统计页面应在顶部提供两张简洁的 Material 3 卡片：摘要卡使用 Material 图标与文字展示所选范围的工作时长、休息时长与完成休息次数；可视化卡使用 24 小时本地时间轴展示所选日期的工作与完整休息时段。中途结束、超时和未完成计时不得被绘入完整休息。

## 7. 界面与交互要求

### 7.1 总体风格

- 现代、简洁、低干扰；
- 信息层级清晰，突出当前状态和已用时间；
- 避免复杂的仪表盘和装饰性元素；
- 兼顾长时间使用时的舒适度和可读性。

### 7.2 平台规范

- Android、Windows、macOS 三端统一使用 Flutter Material 3 组件、主题、对话框、开关、滑块和导航模式。
- 三端共享颜色、字体、组件状态、信息架构和核心交互，避免为每个平台维护一套独立 UI。
- 根据屏幕尺寸、鼠标键盘、窗口尺寸和平台使用习惯做响应式适配；适配不应改变核心功能和视觉语言。
- 通知、权限、系统托盘、菜单栏和亮屏状态等系统能力可以使用平台原生实现，但不替换主要业务界面。
- 跨平台共享信息架构、状态模型和业务规则；平台差异通过适配层处理。
- macOS 系统显示名称按系统语言本地化：英文系统显示 `rest eye`，中文系统显示 `眸息`；技术包名和可执行文件名保持现有值。

### 7.3 建议页面

- **首页**：当前状态、已工作/已休息时间、开始、开始休息和结束计时等主要操作；工作、提醒和休息状态使用不同颜色区分；工作和休息时长摘要可点击，并通过弹窗快速调整对应时长；
- **统计**：顶部提供默认今天的单日期选择器，先展示带 Material 图标的工作、休息和完成休息摘要卡，再展示所选日期的 24 小时工作/休息时间轴卡；工作蓝与休息暖橙必须在浅色、深色主题下保持清晰区分；
- **设置**：以无分类标题和无装饰性左侧图标的紧凑卡片，按“外观 → 通知 → 计时 → 关于”排列；工作提醒、休息提醒、未休息/未工作重复提醒、两类提醒间隔和 Android 震动属于通知卡片，四类通知开关在 Android、Windows、macOS 均可用；工作/休息时长、休息结束后、未休息/休息超时时间、两类超时后处理和“锁屏暂停计时”属于计时卡片，后者默认关闭；Android 外观卡片提供默认开启的固定竖屏开关，Windows 外观卡片提供默认开启的“关闭时最小化到托盘”开关，macOS 外观卡片提供默认开启的“关闭时保留在菜单栏”开关；包括主题模式、显示语言和进入“关于”的二级入口，所有有效修改自动保存；
- **关于（二级页面）**：应用名称、版本和护眼提示，从设置页进入并支持返回。

## 8. 技术设计约束

项目基于 Flutter，目标是共享业务逻辑，同时保留各平台的原生能力。

### 8.1 当前项目约束

- 跨平台构建按当前开发宿主机分阶段执行：当前在 Windows 环境时，优先构建和验证 Android、Windows，macOS 构建可以暂缓；当前切换到 macOS 环境时，优先构建和验证 macOS，Windows 构建可以暂缓。
- 暂缓某个平台的构建不代表取消该平台支持；业务逻辑、界面结构和平台适配接口仍需保留跨平台设计。
- 本项目不编写任何单元测试。功能验证以人工操作、平台运行验证和必要的构建检查为准。

建议拆分为以下边界：

1. **计时领域层**：维护状态机、时间计算、状态转换和事件记录。
2. **通知适配层**：向统一接口提供 Android、Windows、macOS 的原生通知实现。
3. **设备状态适配层**：提供锁屏事件接口，由锁屏暂停控制器和统计记录器消费。
4. **设置与持久化层**：保存用户配置和必要的计时/统计数据。
5. **展示层**：使用统一 Material 3 视觉语言，并根据窗口和输入方式做响应式布局与操作反馈适配。

业务层不能直接依赖某一平台的通知 API；通知按钮触发的操作必须回到计时领域层统一处理。

## 9. 非功能需求

- 应用重启后，设置不能丢失；活动计时的恢复策略需要在实现阶段明确并经过测试。
- 通知权限被拒绝时，应用需要在设置或相关场景提供可理解的引导。
- 时间计算应使用可靠的时间源，避免单纯依赖 UI 刷新次数。
- 计时任务应避免重复创建、重复触发和后台资源持续占用。
- 关键状态转换、通知操作、超时逻辑和统计口径需要通过人工操作和平台运行验证进行检查。
- UI 在常见窗口尺寸和系统缩放比例下应保持可用。

## 10. MVP 范围

### 首期必须实现

- 手动工作计时与休息计时；
- 工作时长和休息时长自定义；
- 原生通知；
- 通知中的开始休息与结束计时；
- 直接开始休息与结束计时；
- Android 震动开关；
- 工作提醒、休息提醒、未休息重复提醒和未工作重复提醒的独立开关；
- 未休息重复提醒和可配置的超时处理（默认进入下一轮）；
- 未工作重复提醒和可配置的休息超时处理（默认进入下一轮）；
- 基础统计：工作时长、休息时长、休息次数；
- Android、Windows、macOS 的基础运行支持。

### 暂缓实现

- 周/月趋势和更复杂的统计分析；
- 云同步、多设备同步；
- 账号体系；
- 社交、激励或复杂任务系统。

## 11. 验收要点

- 使用默认配置时，工作计时结束后能收到休息提醒，并能从应用或通知开始 20 秒休息。
- 休息时间用完后能收到工作提醒，并记录 1 次休息及对应休息时长。
- 结束计时后，不会再触发当前轮休息等待的重复提醒。
- 未开始休息时，按配置间隔提醒；超过配置超时时间后按设置进入下一轮或结束计时。
- 选择继续休息时，按配置间隔提醒开始工作；超过休息超时时间后按设置进入下一轮或结束计时，超时部分计入休息时长。
- 修改配置并重启应用后，配置仍然生效。
- 设置页修改有效值后无需点击保存按钮即可持久化；非法组合不会覆盖最近一次有效设置。
- 主题模式支持跟随系统、浅色和深色，默认跟随系统；语言支持跟随系统、中文和英文，默认跟随系统。
- 首页点击工作或休息时长可打开快捷设置弹窗；正在计时时保存会先弹框确认停止当前计时，未计时直接保存；新时长从下一轮开始使用。
- 开启“锁屏暂停计时”后，Android 锁屏时工作中暂停剩余时间、解锁后恢复同一轮；等待休息和休息阶段不受锁屏影响。
- Android 震动开关关闭时，通知不触发震动；打开时按系统权限和设置执行。
- 分别关闭工作提醒、休息提醒、未休息重复提醒或未工作重复提醒后，对应通知不再排程；两类重复提醒使用各自设置的提醒间隔。
- “锁屏暂停计时”默认关闭；开启后 Android 以 Keyguard 锁屏为暂停信号，Windows 以会话锁定事件、macOS 以系统锁屏事件为暂停信号，恢复后继续同一轮；显示器单独熄灭不触发暂停。
- Android、Windows、macOS 均能使用对应平台的原生通知通道。
- Windows 开启托盘设置后，点击窗口关闭只隐藏到系统托盘；从托盘可打开恢复窗口、退出可真正结束进程，并根据计时状态显示动态计时菜单。macOS 的菜单栏状态项提供相同动作；关闭对应设置后窗口关闭直接退出。
- 统计数据与实际完成的休息行为一致，中途结束和超时不会被错误计为完整休息。
